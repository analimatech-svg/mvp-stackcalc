🚀 Instalação Rápida

1

Instale via npm (requer Node.js 18+)

terminal 
npm install -g @anthropic-ai/claude-code
2

Navegue até o seu projeto e inicie

terminal 
cd meu-projeto
claude
3

Inicialize o arquivo CLAUDE.md do projeto

slash command 
/init
Referência

Principais Arquivos

O Claude Code usa um conjunto de arquivos especiais para personalizar seu comportamento. Conhecer cada um é essencial para trabalhar com eficiência.

📝

CLAUDE.md

./CLAUDE.md  |  ~/.claude/CLAUDE.md

O arquivo mais importante. Funciona como um "briefing" permanente para o Claude. Tudo que está aqui é lido automaticamente no início de cada sessão.

  • Contexto do projeto (stack, arquitetura)
  • Comandos de build, test e lint
  • Convenções de código do time
  • Regras e restrições específicas
  • Variáveis de ambiente necessárias
💡
Dica

Use /init para gerar um CLAUDE.md inicial automaticamente com base no seu projeto.

CLAUDE.md — exemplo 
# Projeto: Minha App

## Stack
- Next.js 14 + TypeScript
- PostgreSQL + Prisma ORM
- Tailwind CSS

## Comandos
- npm run dev    → servidor local
- npm run test   → testes com Vitest
- npm run lint   → ESLint + Prettier

## Convenções
- Componentes: PascalCase
- Funções: camelCase
- Nunca commitar arquivos .env
⚙

settings.json

~/.claude/settings.json

Configurações globais do Claude Code. Define permissões, modelo padrão, hooks e comportamentos automáticos.

  • Permissões de ferramentas (allow/deny)
  • Modelo de IA padrão
  • Configuração de hooks
  • Preferências de interface
JSON 
{
  "model": "claude-opus-4-6",
  "permissions": {
    "allow": [
      "Bash(git:*)",
      "Bash(npm:*)"
    ],
    "deny": [
      "Bash(rm -rf:*)"
    ]
  },
  "hooks": {
    "PostToolUse": [...]
  }
}
⚠
Atenção

Existe também .claude/settings.json por projeto, que sobrescreve o global.

🚫

.claudeignore

./.claudeignore

Similar ao .gitignore. Lista padrões de arquivos e pastas que o Claude não deve ler ou modificar durante a sessão.

  • Arquivos sensíveis (.env, secrets)
  • Pastas geradas (node_modules, dist)
  • Arquivos de build e cache
  • Dados pessoais ou confidenciais
.claudeignore 
# Segredos
.env
.env.local
*.pem
secrets/

# Gerados
node_modules/
dist/
.next/
coverage/

# Logs
*.log
npm-debug.log*
⌨

keybindings.json

~/.claude/keybindings.json

Personaliza os atalhos de teclado do Claude Code. Permite criar atalhos customizados para ações frequentes.

  • Rebind de teclas existentes
  • Criação de chord shortcuts
  • Atalhos para slash commands
  • Aceleração de ações repetitivas
JSON 
[
  {
    "key": "ctrl+shift+c",
    "command": "/commit"
  },
  {
    "key": "ctrl+shift+r",
    "command": "/clear"
  }
]

Comandos Slash

Comandos especiais digitados diretamente no chat, iniciados com /. São atalhos poderosos para ações frequentes.

Comando O que faz Quando usar
/help Mostra todos os comandos disponíveis e atalhos Sempre que precisar de ajuda rápida
/init Analisa o projeto e gera um CLAUDE.md inicial automaticamente Primeiro uso em qualquer projeto
/clear Limpa o histórico da conversa atual e libera contexto Sessão longa ou para trocar de tarefa
/compact Comprime o histórico em um resumo, mantendo contexto essencial Janela de contexto chegando ao limite
/memory Abre e edita o arquivo CLAUDE.md global do usuário Adicionar preferências permanentes
/commit Gera uma mensagem de commit semântica e faz o commit das mudanças Após concluir uma feature ou correção
/review-pr Faz revisão completa de um Pull Request aberto Antes de aprovar PRs do time
/pr-comments Lista e responde comentários de um PR do GitHub Durante revisão de código colaborativa
/cost Mostra o uso de tokens e custo estimado da sessão atual Monitorar consumo de API
/status Exibe o status atual: modelo, permissões e sessão Verificar configurações ativas
/fast Ativa/desativa o modo rápido (Fast Mode) para respostas mais ágeis Tarefas simples que precisam de velocidade
/bug Abre formulário para reportar um bug do Claude Code Comportamento inesperado da ferramenta
/logout Encerra a sessão e remove credenciais salvas Troca de conta ou máquina compartilhada

Comandos CLI

Flags e modos da linha de comando para automatizar, integrar e controlar o Claude Code fora do modo interativo.

Modo Interativo (padrão)

terminal 
# Inicia o REPL interativo na pasta atual
claude

# Inicia com um prompt inicial já enviado
claude "explique a arquitetura deste projeto"

# Abre em pasta específica
claude --dir /caminho/do/projeto

Modo Print (não-interativo)

terminal 
# Responde e sai imediatamente (ideal para scripts)
claude --print "gere um relatório de cobertura de testes"

# Alimentar via stdin (pipeline)
cat erros.log | claude -p "analise estes erros"

# Saída em formato JSON
claude --print --output-format json "liste os endpoints da API"

Tabela de Flags Principais

Flag Alias Descrição
--print -p Modo não-interativo: executa e sai
--model -m Escolhe o modelo: claude-opus-4-6, claude-sonnet-4-6, claude-haiku-4-5
--output-format — Formato de saída: text (padrão), json, stream-json
--dir -d Define o diretório de trabalho
--resume — Retoma uma sessão anterior pelo ID
--continue -c Continua a última sessão automaticamente
--dangerously-skip-permissions — ⚠ Pula todas as confirmações de permissão. Use apenas em CI/CD controlado
--allowedTools — Lista de ferramentas permitidas para a sessão
--verbose — Exibe logs detalhados das chamadas de ferramentas
--version -v Exibe a versão instalada

Exemplos de Uso em CI/CD

bash — pipeline de automação 
#!/bin/bash
# Revisa o diff antes do merge
git diff main..HEAD | claude -p \
  "revise este diff e aponte problemas de segurança"

# Gera changelog automaticamente
claude -p --model claude-sonnet-4-6 \
  "gere um CHANGELOG.md com base nos commits desde v1.0.0"

# Verifica documentação desatualizada
claude -p "compare README.md com o código atual e liste discrepâncias"
⚠
Cuidado com --dangerously-skip-permissions

Esta flag desativa todas as proteções de segurança. Nunca use em produção ou com acesso a dados sensíveis. Use apenas em ambientes CI/CD isolados e controlados.

Organização

Estrutura de Pastas Recomendada

Uma boa organização de pastas ajuda o Claude a entender o projeto mais rapidamente e trabalhar com mais precisão desde a primeira mensagem.

🏠 Pasta Global do Claude Code

~/.claude/ ├── CLAUDE.md # instruções globais ├── settings.json # config global ├── keybindings.json # atalhos customizados ├── commands/ # seus slash commands │ ├── deploy.md │ ├── review.md │ └── standup.md ├── mcp/ # servidores MCP │ └── config.json └── plans/ # planos salvos

📁 Pasta do Projeto (ideal)

meu-projeto/ ├── CLAUDE.md # contexto do projeto ★ ├── .claudeignore # exclusões do Claude ├── .claude/ │ └── settings.json # config local ├── src/ # código-fonte ├── tests/ # testes ├── docs/ # documentação ├── .env.example # template de variáveis ├── .gitignore └── README.md
💡
Por que a estrutura importa?

O Claude lê o CLAUDE.md do projeto antes de qualquer coisa. Se o arquivo descreve bem a arquitetura, os comandos de build e as convenções, o Claude trabalha com muito mais precisão — sem precisar "adivinhar" o contexto a cada sessão.

Criando Slash Commands Customizados

Arquivos .md dentro de ~/.claude/commands/ viram automaticamente slash commands disponíveis em qualquer projeto.

~/.claude/commands/standup.md 
# /standup — Gera relatório de standup diário

Analise os commits do dia de hoje com `git log --since="24 hours ago"`.

Gere um relatório de standup no formato:
- **O que foi feito:** (baseado nos commits)
- **O que será feito:** (próximas tarefas óbvias)
- **Impedimentos:** (erros ou TODOs encontrados no código)

Seja conciso e use bullet points.

Agora basta digitar /standup no chat para executar.

Boas Práticas de Uso

Pequenas mudanças na forma como você interage com o Claude fazem uma grande diferença nos resultados. Siga estas práticas para sessões mais eficientes.

💬 Escrevendo Bons Prompts

  • Seja específico: informe o arquivo, função ou comportamento exato
  • Dê contexto suficiente — mencione a stack, a versão e o objetivo
  • Use "não faça X" para guiar restrições importantes
  • Peça confirmação antes de mudanças destrutivas
  • Divida tarefas grandes em etapas menores e sequenciais
  • Prefira descrever o resultado esperado, não o como fazer
  • Use /compact quando a sessão ficar longa demais
  • Inclua exemplos quando o formato de saída importar

📝 CLAUDE.md Eficiente

  • Inclua os comandos de build, test e lint logo no início
  • Liste as convenções de código do time (naming, estilo)
  • Documente decisões de arquitetura importantes
  • Informe quais pastas são geradas e devem ser ignoradas
  • Adicione exemplos de código quando houver padrões específicos
  • Revise e atualize após grandes mudanças no projeto
  • Use seções claras com headers Markdown
  • Evite informações redundantes — seja conciso

Modelo de CLAUDE.md Completo

CLAUDE.md — template profissional 
# Projeto: Nome do Projeto
# Descrição breve do que o projeto faz

## Stack Tecnológica
- Runtime: Node.js 20 / Python 3.12
- Framework: Next.js 14 / FastAPI
- Banco de dados: PostgreSQL 16 + Prisma
- Testes: Vitest + Testing Library
- CI/CD: GitHub Actions

## Comandos Essenciais
```bash
npm run dev        # Servidor de desenvolvimento (porta 3000)
npm run build      # Build de produção
npm run test       # Testes unitários
npm run test:e2e   # Testes end-to-end (requer DB rodando)
npm run lint       # ESLint + Prettier
npm run db:migrate # Aplicar migrações Prisma
```

## Arquitetura
- src/app/      → páginas Next.js (App Router)
- src/components/ → componentes React reutilizáveis
- src/lib/      → utilitários e helpers
- src/api/      → chamadas externas de API
- prisma/       → schema e migrações do banco

## Convenções de Código
- Componentes React: PascalCase (ex: UserCard.tsx)
- Funções e variáveis: camelCase
- Constantes: UPPER_SNAKE_CASE
- Arquivos de teste: *.test.ts ou *.spec.ts
- Commits: Conventional Commits (feat, fix, chore...)

## Variáveis de Ambiente (necessárias)
- DATABASE_URL → string de conexão PostgreSQL
- NEXTAUTH_SECRET → segredo para autenticação
- API_KEY_EXTERNAL → chave da API externa XYZ

## Restrições
- Nunca commitar arquivos .env ou .env.local
- Não modificar arquivos em dist/ ou .next/
- Migrations do Prisma: sempre revisar antes de aplicar em prod

🚫 O Que Evitar

❌

Prompts Vagos

Evite: "arruma o bug" ou "melhora o código". Seja específico sobre qual arquivo, qual comportamento e qual resultado esperado.

❌

Sessões Infinitas

Uma sessão muito longa perde contexto. Use /compact ou inicie uma nova sessão para cada tarefa principal com /clear.

❌

Sem CLAUDE.md

Trabalhar sem um CLAUDE.md faz o Claude ter que "adivinhar" o contexto a cada sessão, reduzindo muito a qualidade das respostas.

❌

Skip de Permissões

Usar --dangerously-skip-permissions no dia a dia é perigoso. Reserve para pipelines CI/CD isolados com acesso controlado.

Recursos Avançados

Depois de dominar o básico, estes recursos permitem automações poderosas, integrações externas e controle fino do comportamento do Claude.

🔌 MCP Servers (Model Context Protocol)

MCP é um protocolo aberto que permite conectar o Claude a ferramentas e dados externos — como bancos de dados, APIs, sistemas de arquivos remotos, Slack, GitHub, e muito mais.

📊

MCP de Banco de Dados

Conecte o Claude diretamente ao PostgreSQL, MySQL ou SQLite. Ele pode consultar, analisar dados e até sugerir queries complexas.

Popular
🔨

MCP do GitHub

Acesso completo a issues, PRs, repositórios e code review diretamente no Claude Code, sem sair da sessão.

Incluído
📈

MCP Customizado

Crie seu próprio servidor MCP em Node.js ou Python para integrar qualquer sistema interno da sua empresa.

Avançado
~/.claude/settings.json — configurando MCP 
{
  "mcpServers": {
    "meu-banco": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-postgres"],
      "env": {
        "DATABASE_URL": "postgresql://user:pass@localhost/db"
      }
    },
    "filesystem": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-filesystem", "/home/user/docs"]
    }
  }
}

🔗 Hooks — Automações de Evento

Hooks são scripts shell executados automaticamente em resposta a eventos do Claude Code. Perfeitos para automações como logging, validação e notificações.

Evento Quando dispara Caso de uso comum
PreToolUse Antes de qualquer ferramenta ser executada Validar comandos, bloquear ações perigosas
PostToolUse Após a execução de uma ferramenta Logging, notificações, testes automáticos
SessionStart Ao iniciar uma nova sessão do Claude Code Setup do ambiente, checar dependências
SessionEnd Ao encerrar a sessão Relatórios, limpeza de temporários
Notification Quando o Claude envia uma notificação Alertas no Slack, desktop notifications
settings.json — hook de log automático 
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "echo \"$(date): Bash executado\" >> ~/.claude/audit.log"
          }
        ]
      }
    ],
    "SessionStart": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "npm run check-env 2>/dev/null || true"
          }
        ]
      }
    ]
  }
}

🔒 Modos de Permissão

👥

Modo Padrão

O Claude pede confirmação antes de executar ações potencialmente destrutivas (deletar arquivos, executar scripts, etc.).

Recomendado para uso diário

🔧

Allow/Deny Rules

Defina regras granulares em settings.json para permitir ou bloquear ferramentas e comandos específicos sem interrupção.

"allow": ["Bash(git:*)", "Bash(npm:*)"]
"deny":  ["Bash(rm:*)", "Bash(curl:*)"
⚠

Skip Permissions Perigo

Flag --dangerously-skip-permissions: pula todas as confirmações. Use somente em containers isolados de CI/CD. Nunca em máquinas locais com dados reais.
